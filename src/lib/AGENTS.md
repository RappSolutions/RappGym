- Home dashboard numbers come from the pure `src/lib/dashboard.ts` module (tested); soft training goals live in the owner-scoped `training_goals` table and are passed to the AI insight call as untrusted data, so AI advice can reflect goals without trusting them as instructions.
- Exercise categories (name, code prefix, colour token) and equipment are FK lookup tables read via EXERCISE_SELECT/normalizeExercise in `src/lib/exercise-refs.ts`; new codes come from the category's DB prefix, never from code constants, so admins own the vocabulary.
- AI quota: ai_quota_status() in the DB is the single source (tier -> custom -> block, admin unlimited, counted from saved training_ai_history rows per UTC month); the server fn checks it before any AI call and UI only mirrors it, so failed calls never consume quota.
- Per-user AI exercise ratings live in sparse user_exercise_preferences (missing = normal); rating 1 is filtered server-side before the AI call and 5 is mandatory in the prompt, so vetoes never depend on model obedience. AI history is compressed to the last 10 workout days plus latest kg per exercise/gym, so prompt size stays constant.
- Contact messages are stored before Elastic Email delivery; use a server-only helper, fixed recipient/sender and auth-derived Reply-To, and return saved-but-not-sent on failure so no message is lost or falsely reported sent.
- Exercise suggestions live in their own owner-scoped table with category/equipment FKs; the shared dialog never writes exercises, and only explicit submission sends email after persistence.
- Exercise name URL lookup is shared by both forms, authenticated and bounded; validate public destinations and every redirect, preserve links before lookup, and discard stale responses so external titles never overwrite newer edits.
- The authenticated layout owns one URL-driven runner; tab-scoped recovery includes cursor, temporary skips, input targets and lap timing, so auth remounts do not reset training. Completion records lap/set ordinals; never backfill inferred historical positions. Lap estimates extrapolate the same phase only, with one-minute rests; spontaneous workouts have no remaining-time estimate.
- Exercise browsing reuses ExerciseDetails and the fixed-exercise ProgressOverview; history uses FK identity and recorded units, while the shared spontaneous start writes only a workout/plan and ExerciseForm returns normalized FK joins, preventing duplicate UI logic and fact mutation.
- Workout print and log Excel export share the pure src/lib/workout-export.ts (PDF via jspdf, xlsx via SheetJS; both statically imported and generated synchronously in the click so user activation survives); exports read completed facts only, so no app print CSS or plan/fact mixing.
- Tonnage is derived on the fly by the pure src/lib/tonnage.ts (per log row sets × reps × numeric kg; time/bodyweight excluded) and only burned in at Excel export, so formula changes never need data migrations.
- Home statistics lead with the tonnage chart (day / ISO week / kg per min) from pure series functions in src/lib/tonnage.ts, so charts and exports share one formula.
- Terms consent: append-only user_consents(user_id, terms_version int); ConsentGate prompts when max accepted < CURRENT_TERMS_VERSION (src/lib/consent.ts), so bumping the constant re-prompts everyone.
