- Home dashboard numbers come from the pure `src/lib/dashboard.ts` module (tested); soft training goals live in the owner-scoped `training_goals` table and are passed to the AI insight call as untrusted data, so AI advice can reflect goals without trusting them as instructions.
- Exercise categories (name, code prefix, colour token) and equipment are FK lookup tables read via EXERCISE_SELECT/normalizeExercise in `src/lib/exercise-refs.ts`; new codes come from the category's DB prefix, never from code constants, so admins own the vocabulary.
- AI quota: ai_quota_status() in the DB is the single source (tier -> custom -> block, admin unlimited, counted from saved training_ai_history rows per UTC month); the server fn checks it before any AI call and UI only mirrors it, so failed calls never consume quota.
- Per-user AI exercise ratings live in sparse user_exercise_preferences (missing = normal); rating 1 is filtered server-side before the AI call and 5 is mandatory in the prompt, so vetoes never depend on model obedience. AI history is compressed to the last 10 workout days plus latest kg per exercise/gym, so prompt size stays constant.
- Contact messages are stored before Elastic Email delivery; use a server-only helper, fixed recipient/sender and auth-derived Reply-To, and return saved-but-not-sent on failure so no message is lost or falsely reported sent.
- Exercise suggestions live in their own owner-scoped table with category/equipment FKs; the shared dialog never writes exercises, and only explicit submission sends email after persistence.
